# manifest — personal manifestation notifier

Texts your own manifestation statements to you via iMessage on a schedule (launchd), with every send counted in `~/manifest/manifest.db`.

**Setup:** clone, then `python3 manifest.py install` — it puts `manifest` on your PATH, creates the DB, asks for your number/Apple ID, and loads the launchd agent (default times 08:00, 13:00, 21:00). `manifest uninstall` reverses it (the DB and send history are kept).

**Commands:** `add "text"` · `list` · `edit <id> "new text"` · `pause <id>` / `resume <id>` · `remove <id>` (soft delete) · `times 08:00 13:00 21:00` (rewrites the plist and reloads launchd) · `random 18` (N fresh random times each day between 08:00–21:30, reshuffled nightly at 00:10 — or at login if the Mac was off then; `random off` to stop) · `send-now` (test send, logged as slot `manual`) · `stats` · `status` (power source, next slot, anything missed and still due, loaded agents, scheduled wakes) · `autowake on|off` (see below) · `channel ntfy --topic X` (fallback channel, iMessage is the default).

Message changes apply on the next send with no reload; only `times` / `random` touch launchd. **Upgrading** an existing install: pull, then run `manifest install` once so both launchd agents are regenerated.

**Sleep, lid closed, power off — nothing is lost:** launchd cannot run anything while the Mac is asleep or off. The moment it wakes (launchd replays intervals missed during sleep) or you log in after a boot (both agents have `RunAtLoad`), the agent sends every slot that came and went without a delivery, one message at a time a few seconds apart, oldest first (up to 24 h back, never before the schedule was last changed). Every slot occurrence is delivered exactly once: sends are recorded per occurrence, a failed attempt (Wi-Fi or Messages not ready yet) is retried three times on the spot and again on the next run, a schedule change first finishes the old schedule and never backfills the new times, and a process lock keeps the nightly reshuffle from interrupting a catch-up in progress. `manifest status` shows what is due right now.

**Unplugged / battery:** the agent logs the power source (`pmset -g batt`) on every run and `status` shows it live. `manifest autowake on` makes the Mac wake itself one minute before each slot (and before the 00:10 reshuffle) via `pmset schedule wakeorpoweron`, re-armed after every run; it installs a one-line passwordless sudo rule for `pmset schedule` in `/etc/sudoers.d/manifest` (asks for your password once, validated with `visudo`; `autowake off` removes it). Apple only guarantees scheduled wakes when a notebook is connected to power: on battery with the lid closed macOS may not wake, and then the catch-up on lid-open is the safety net. A Mac-independent guarantee (texts arriving while the Mac is shut in a bag for days) needs the scheduler to live somewhere always-on — that is a different design (cloud scheduler + the ntfy channel), not something this agent can do from the laptop.

**Timezones:** slots are wall-clock local time. Flying west repeats a few hours and those slots were already sent for that occurrence; flying east skips them. That is by design.

**Automation permission:** the first Terminal send prompts you; the launchd path often doesn't. Test it with `launchctl kickstart -k gui/$(id -u)/com.manifest.agent` (within 20 min of a slot, or temporarily add a near slot via `manifest times`). If it logs `failed`, allow the Python listed in `~/Library/LaunchAgents/com.manifest.agent.plist` (and `/usr/bin/osascript`) to control Messages under System Settings → Privacy & Security → Automation, then kickstart again.
